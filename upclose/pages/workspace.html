Sublead Conversations

Two-way SMS with this client's subleads isn't wired up yet. The Twilio inbound router (FIND CONTACT) currently resolves an incoming number against crm.clients and crm.leads only, so a sublead's reply has nowhere to land.

Backend required
  • Extend FIND CONTACT with a crm.subleads branch and define precedence on phone collisions
  • Write sublead_id in SAVE INBOUND SMS
  • An outbound send endpoint scoped to sublead_id + client_id

Agency conversations are unaffected and remain in the Communication Hub.

campaign

Campaigns

No campaign data exists anywhere in the system yet — there is no table, no workflow and no ad-platform connection. Rather than show an empty chart, this page stays honest until there is something real to display.

Backend required
  • A crm.campaigns table keyed by client_id
  • Attribution from crm.subleads.source / metadata to a campaign
  • Ad spend ingestion per campaign and per period
insights

Funnels

Subleads currently carry status and source only. There are no stage, booking, show, offer or value fields, so cost-per-stage and conversion metrics cannot be calculated for a client's funnel.

Backend required
  • Funnel columns on crm.subleads (stage, booked_at, showed, offer_made, value)
  • Per-client ad spend, stored server-side rather than in the browser

The agency-level Funnel Metrics page is unchanged.

Client Reports

Client reporting needs a metric set that doesn't exist yet. Subleads have no stage history, no value and no campaign attribution, so any report today would be a count of rows by status — which the Overview page already shows honestly.

Backend required
  • Sublead stage history (audit rows with sublead_id)
  • Campaign attribution and per-client spend
  • Review outcome data (delivery status from the Twilio callback)
